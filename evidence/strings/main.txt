"Self-exit when the parent process (the frontend that spawned this sidecar)\n    dies, so closing/killing the app releases the webcam even on an abnormal exit.\n\n    The Unix-domain-socket watcher below is a no-op on Windows, so without this the\n    sidecar would be orphaned with the camera held open until its last gRPC client\n    (the runtime inside the client app) disconnects. "Deterministic parent-death detector for the auto-launched case.\n\n    When xrsim (MetaXRSimulator) spawns this sidecar, it hands us the path\n    of a Unix-domain socket it is holding open (via ``XRSIM_PARENT_SOCK_PATH``).\n    We connect to it and block on ``recv()``. When the parent process dies\n    for ANY reason — clean exit, SIGKILL, kernel panic — the OS closes\n    the parent's socket, the peer end here returns EOF, and we self-exit\n    within OS scheduling latency (~ms). No polling, no timeout, no false\n    negatives on abrupt parent death.\n\n    No-op when the env var is absent (manual CLI runs). The sidecar then\n    persists indefinitely under operator control. On Windows the Unix-domain\n    socket is unavailable, so a process-handle watcher is used instead (see\n    _install_windows_parent_liveness_watcher).\n    "
